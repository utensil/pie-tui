## Boundary

`pie_core::editor_model` is a rank-0 state reducer. It stores owned text, cursor, paste registry,
history, kill ring, undo snapshots, and navigation state. It does not retain or execute callbacks,
perform I/O, render, schedule timers, create futures, or depend on a TUI. Each action returns an
ordered list of `Change` and `Submit` effects for a higher layer to deliver.

## Coordinates and ownership

- Public cursor columns use UTF-16 code units, matching JavaScript string indices.
- Cursor movement and character deletion use extended grapheme clusters, including combining
  sequences, emoji modifiers, and ZWJ emoji.
- A paste marker is atomic only while its numeric ID exists in the owned paste registry.
- An owned marker remains one logical edit segment even when it is wider than the viewport. Its
  visual representation is recursively split only at grapheme boundaries, without joining visual
  subchunks from adjacent markers; vertical movement preserves the pre-snap column while skipping
  or snapping marker-continuation rows.
- Undo snapshots clone all owned editor state that the reference snapshots: lines/cursor, paste
  contents, and paste counter. Kill ring and history remain outside undo snapshots.

## State transitions

- Text normalization maps CRLF and CR to LF, then expands each tab to four spaces.
- Programmatic set/insert and paste are each one undo unit. Typed non-whitespace coalesces until a
  whitespace boundary; the whitespace and following word form the next undo unit.
- Submitting first resets the state and yields `Change("")`, then yields the trimmed expanded text
  as `Submit(value)`. Submission clears undo state.
- A paste remains inline at ten logical lines and becomes `[paste #N +11 lines]` at eleven. Text
  longer than 1000 UTF-16 units uses the character-count marker form.
- Submission expands paste markers sequentially in registry insertion order and replaces every
  spelling for each ID, so a replacement may expose another registered marker for a later pass.
- Entering history saves the draft once. Previous-history placement is at the start; next-history
  placement is at the end; leaving history restores the exact saved draft state.
- Consecutive backward kills prepend, consecutive forward kills append, yank uses the newest entry,
  and yank-pop replaces the prior yank while rotating older entries.
- Vertical and page navigation preserve the preferred UTF-16 column across shorter logical or
  wrapped rows, and clear it once the preferred column fits again.

## Word-segmentation verification boundary

The pure fallback pins `unicode-segmentation = 1.12.0`, `icu_segmenter = 2.0.0`,
`icu_locale_core = 2.0.0`, and `icu_provider = 2.0.0`. Unicode 16 UAX 29 supplies the ordinary
boundary shell. The ICU4X dictionary constructor is used only for contiguous Thai/CJK complex
spans, followed by the bounded ICU 77 Thai-to-non-CJK status/boundary reconciliation.

The committed Node receipt enumerates the Cartesian product of 14 Latin, Thai, CJK, combining,
prepend, punctuation, whitespace, underscore, and Unicode-sentinel atoms at lengths one through
four: 41,370 strings and 250,044 scalar-valid UTF-16 boundaries. All 30,940 non-Thai strings and
152,126 boundaries are exact (`df413813a4063b8e`). The isolated Thai dictionary witness `พัชรี`
is exact at every boundary and kills the auto-constructor mutant; focused vectors cover
`完成作业`, mixed Latin/CJK/Thai, combining/prepend, punctuation, U+11A3A, and U+1ACF.

This fallback is deliberately **partial**, not universally reference-exact. The receipt names
1,439 Thai-adjacent ICU4X/ICU 77 lexicon divergences (`bf789ac4bcd5b222`), including repeated Thai
and Thai-plus-combining attachment. `แพนด้าแดง` is exact as a whole segmentation but retains
interior prefix/suffix navigation debt. M5's host/TypeScript adapter must supply the host
`Intl.Segmenter` through `WordNavOptions.segment` before claiming complete locale-dictionary
parity.
